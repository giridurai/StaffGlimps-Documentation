### Development

When running on `localhost`, all services are proxied through a single `/api` prefix:

```
http://localhost:4200/api/<service-path>
```

The Angular proxy configuration rewrites `/api` requests to the appropriate live endpoints, so you don't need to manage CORS or separate base URLs during development.

## Authentication

Every API request (except public document downloads) must include **two headers**:

| Header           | Value                                          | Required |
| ---------------- | --------------------------------------------- | -------- |
| `Authorization`  | `Bearer <AWS_Cognito_ID_Token>`               | Yes      |
| `x-api-key`      | Static shared key                              | Yes      |

### Obtaining a Bearer Token

StaffGlimpse uses **AWS Cognito** for user authentication. After a successful login, your application obtains an ID token via the Amplify Auth library:

```typescript
import { fetchAuthSession } from 'aws-amplify/auth';

const session = await fetchAuthSession();
const token = session.tokens?.idToken?.toString();
```

### x-api-key

The `x-api-key` header contains a static shared secret, the same value across all service gateways. You cannot make any authenticated API call without it.

## Response Format

All successful responses follow a consistent envelope:

```json
{
  "message": "Human-readable summary",
  "responseCode": 200,
  "response": "Success",
  "result": {
    // endpoint-specific payload
  }
}
```

- `responseCode: 200` indicates success.
- `result` is the actual data payload; its shape varies per endpoint.
- Error responses use standard HTTP status codes (400, 401, 403, 404, 500).
