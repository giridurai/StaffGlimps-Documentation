### Development

When running on `localhost`, all services are proxied through a single `/api` prefix:

```
http://localhost:4200/api/<service-path>
```

The Angular proxy configuration rewrites `/api` requests to the appropriate live endpoints, so you don't need to manage CORS or separate base URLs during development. The codebase automatically switches between development and production base URLs — see `src/app/core/const/api-urls.ts`.

## Authentication

Every API request (except public document downloads) must include **two headers**:

| Header           | Value                                          | Required |
| ---------------- | --------------------------------------------- | -------- |
| `Authorization`  | `Bearer <AWS_Cognito_ID_Token>`               | Yes      |
| `x-api-key`      | `iPS42...Ok` (static key from `GlobalUrls.xApiKey`) | Yes      |

### Obtaining a Bearer Token

StaffGlimpse uses **AWS Cognito** for user authentication. After a successful login, your application obtains an ID token via the Amplify Auth library:

```typescript
import { fetchAuthSession } from 'aws-amplify/auth';

const session = await fetchAuthSession();
const token = session.tokens?.idToken?.toString();
```

The Angular app uses an HTTP interceptor (`src/app/core/interceptors/auth.interceptor.ts`) that automatically attaches both headers to every API request. If you're integrating from a non-Angular client, you must inject these headers manually.

### x-api-key

The `x-api-key` header contains a static shared secret. It is the same value across all service gateways. You cannot make any authenticated API call without it.

## Quickstart

### 1. Register your company

```bash
curl -X POST https://r00buwtnh1.execute-api-ap-south-1.amazonaws.com/live/company/register \
  -H "Content-Type: application/json" \
  -H "x-api-key: iPS42...Ok" \
  -H "Authorization: Bearer <token>" \
  -d '{
    "name": "Acme Corporation",
    "email": "admin@acme.com",
    "password": "SecurePass123!",
    "confirmPassword": "SecurePass123!"
  }'
```

## Response Format

All successful responses follow a consistent envelope:

```json
{
  "message": "Human-readable summary",
  "responseCode": 200,
  "response": "Success",
  "result": {
    // endpoint-specific payload
  }
}
```

- `responseCode: 200` indicates success.
- `result` is the actual data payload — its shape varies per endpoint.
- Error responses use standard HTTP status codes (400, 401, 403, 404, 500).

## API Reference

The full API is documented in the **API Reference** section in the sidebar, organized by service domain:

- **Company** — company profile and registration
- **Departments** — department CRUD
- **Roles & Permissions** — role management, permissions matrix, user counts
- **Users** — user profile, create/update/lock/unlock/delete
- **Metadata** — global configurable metadata entries
- **Messages** — in-app notifications and inbox
- **Attendance** — punch in/out, weekly approval, monthly reports
- **Documents** — upload, list, update, and download documents
- **Leave Policies** — leave policy and holiday configuration (company admin)
- **Leave Requests** — employee leave ledger, requests, and manager approval

You can also explore the complete OpenAPI 3.0 specification in the **OpenAPI Spec** section, which is compatible with tools like Postman, Insomnia, and Swagger UI.

## SDK & Framework Notes

The reference implementation is an **Angular 17+** application using:

- `HttpClient` + `httpResource` for API calls
- AWS Amplify v6 for Cognito authentication (`fetchAuthSession`)
- RxJS `Observable` pipelines with `catchError` for error handling
- An HTTP interceptor that attaches auth headers globally

If you're building a client in another language or framework, you only need:

1. An HTTP client that supports custom headers
2. AWS Cognito SDK (or a compatible JWT provider) for token acquisition
3. The static `x-api-key` value
