StaffGlimpse uses role-based access control to make sure each user can only see and edit the data they need. You can use the built-in roles for common HRMS personas, or create custom roles with fine-grained permissions scoped to specific modules, locations, and departments.

## Default roles

StaffGlimpse ships with six default roles. You can assign these directly or clone them to create variations.

| Role | Typical access |
| --- | --- |
| **Admin** | Full access to all modules, settings, billing, and user management. |
| **HR** | Employee management, attendance, leave, and performance configuration. No billing or security settings. |
| **Manager** | Team attendance, leave approvals, goal and review management for direct reports. Limited employee data outside their team. |
| **Employee** | Self-service only: profile, payslips, attendance, leave requests, and personal goal updates. |
| **Payroll Admin** | Salary structures, payroll processing, payslip generation, and statutory compliance configuration. |
| **Finance** | Payroll reports, cost center summaries, and invoice exports. Cannot edit employee records or run payroll. |

<Warning>
  **Payroll Admin** can view sensitive compensation data for all employees. Only assign this role to trusted finance and payroll staff. Audit role assignments regularly from **Admin** > **Security** > **Audit Logs**.
</Warning>

## Create a custom role

<Steps>
  <Step title="Open roles settings">
    Go to **Admin** > **Roles & Permissions**.
  </Step>
  <Step title="Add a custom role">
    Click **New Role**. Enter a name (for example, "Regional HR Lead") and an optional description.
  </Step>
  <Step title="Set module permissions">
    For each module (Employee Management, Attendance & Leave, Payroll, Performance, Administration), choose one of:

    - **No access**
    - **View only**
    - **View and edit**
    - **Full control**
  </Step>
  <Step title="Restrict by scope">
    Under **Scope**, enable **Restrict by location** and/or **Restrict by department**. Select the locations and departments this role can access. For example, a "Bangalore HR" role might be limited to the Bangalore office and the Engineering department.
  </Step>
  <Step title="Save the role">
    Click **Save**. The role appears in the list and can be assigned to users immediately.
  </Step>
</Steps>

## Assign a role to a user

<Steps>
  <Step title="Find the user">
    Go to **Employee Management** > **Employees**. Search for the user and open their profile.
  </Step>
  <Step title="Edit role">
    Click **Edit** next to **Role & Permissions**. Select the role from the dropdown.
  </Step>
  <Step title="Confirm scope">
    If the role has location or department restrictions, verify the user is assigned to an eligible location and department on the **Job** tab of their profile.
  </Step>
  <Step title="Save">
    Click **Save Changes**. The user receives an in-app notification that their permissions have been updated.
  </Step>
</Steps>

## Result

The user can now access only the modules, locations, and departments allowed by their role. Changes take effect immediately without requiring a logout.
