The Leave Requests API handles the employee-facing side of leave management — submitting requests, checking the leave ledger, and processing manager approvals and rejections. Employees interact with their own requests, while managers access a dedicated view to review and act on their team's pending applications.

**Base URL:** `https://5bknc0zrv5.execute-api.ap-south-1.amazonaws.com/live`

---

## Authentication

Every request to the Leave Requests API requires both of the following headers:

| Header | Value |
|---|---|
| `Authorization` | `Bearer <AWS_Cognito_ID_Token>` |
| `x-api-key` | `<static_shared_key>` |

---

## Leave Request Status Flow

Before calling the API, understand how a leave request moves through its lifecycle:

| From Status | Action | Resulting Status | Who Can Perform |
|---|---|---|---|
| *(none)* | Submit request | `PENDING` | Employee |
| `PENDING` | Manager approves | `APPROVED` | Manager / Admin |
| `PENDING` | Manager rejects | `REJECTED` | Manager / Admin |
| `PENDING` | Employee cancels | `CANCELLED` | Employee |

<Note>
  Only `PENDING` requests can be acted upon. Once a request reaches `APPROVED`, `REJECTED`, or `CANCELLED`, no further status changes are permitted through the API.
</Note>

## POST /leave/request/create

**Submit Leave Request** — create a new leave application for the authenticated employee.

Submit this request as soon as the employee selects their leave dates. The request is created with a `PENDING` status and routed to the employee's assigned manager for review.

### Request Body

<ParamField body="leaveType" type="string" required>
  The type of leave being requested. Must match a type configured in the company's leave policy — e.g., `"Annual"`, `"Sick"`, `"Casual"`.
</ParamField>

<ParamField body="fromDate" type="string" required>
  The first day of the leave period in `YYYY-MM-DD` format.
</ParamField>

<ParamField body="toDate" type="string" required>
  The last day of the leave period in `YYYY-MM-DD` format.
</ParamField>

<ParamField body="days" type="integer" required>
  The total number of leave days being requested. This value must match the span between `fromDate` and `toDate` after excluding weekends and public holidays.
</ParamField>

<ParamField body="reason" type="string" required>
  A brief explanation of the reason for taking leave.
</ParamField>

<ParamField body="documents" type="array">
  Optional array of supporting documents (e.g., medical certificates). Each element must include the following fields:
  <Expandable title="document object fields">
    <ParamField body="documentId" type="string" required>
      The ID of the document as returned by the Documents API after upload.
    </ParamField>
    <ParamField body="documentName" type="string" required>
      The display name of the document file.
    </ParamField>
    <ParamField body="documentContentType" type="string" required>
      MIME type of the document (e.g., `"application/pdf"`, `"image/jpeg"`).
    </ParamField>
  </Expandable>
</ParamField>

<CodeGroup>

```bash cURL
curl -X POST \
  https://5bknc0zrv5.execute-api.ap-south-1.amazonaws.com/live/leave/request/create \
  -H "Authorization: Bearer <YOUR_COGNITO_ID_TOKEN>" \
  -H "x-api-key: <YOUR_API_KEY>" \
  -H "Content-Type: application/json" \
  -d '{
    "leaveType": "Sick",
    "fromDate": "2024-06-18",
    "toDate": "2024-06-19",
    "days": 2,
    "reason": "Viral fever — doctor advised two days of rest.",
    "documents": [
      {
        "documentId": "doc_cert_00123",
        "documentName": "medical_certificate_june2024.pdf",
        "documentContentType": "application/pdf"
      }
    ]
  }'
```

```json Request Body
{
  "leaveType": "Sick",
  "fromDate": "2024-06-18",
  "toDate": "2024-06-19",
  "days": 2,
  "reason": "Viral fever — doctor advised two days of rest.",
  "documents": [
    {
      "documentId": "doc_cert_00123",
      "documentName": "medical_certificate_june2024.pdf",
      "documentContentType": "application/pdf"
    }
  ]
}
```

</CodeGroup>

```json Response
{
  "message": "Leave request submitted successfully.",
  "responseCode": 200,
  "response": "Success",
  "result": {
    "leaveRequestId": "lr_20240618_usr001",
    "status": "PENDING"
  }
}
```

## POST /leave/request/update

**Update Leave Request** — approve, reject, or cancel a leave request. The `type` query parameter determines which action scope is available.

The `type` query parameter controls the permitted actions:
- `type=user` — allows employees to **cancel** their own pending request.
- `type=manager` — allows managers to **approve** or **reject** a team member's pending request.

### Query Parameters

<ParamField query="type" type="string" required>
  The actor's role context. Accepted values: `"user"` or `"manager"`.
</ParamField>

### Request Body

<ParamField body="leaveRequestId" type="string" required>
  The unique identifier of the leave request to update.
</ParamField>

<ParamField body="userId" type="string">
  The user ID of the employee whose leave request is being updated.
</ParamField>

<ParamField body="action" type="string" required>
  The action to perform. Accepted values: `"approve"`, `"reject"`, `"cancel"`, `"resubmit"`, or `"delete"`.
</ParamField>

<ParamField body="comments" type="string">
  Optional remarks from the employee (used when `type=user`).
</ParamField>

<ParamField body="managerComments" type="string">
  Optional remarks from the manager (used when `type=manager`).
</ParamField>

<Tabs>
  <Tab title="Manager Approval">

```bash
curl -X POST \
  "https://5bknc0zrv5.execute-api.ap-south-1.amazonaws.com/live/leave/request/update?type=manager" \
  -H "Authorization: Bearer <YOUR_COGNITO_ID_TOKEN>" \
  -H "x-api-key: <YOUR_API_KEY>" \
  -H "Content-Type: application/json" \

    "leaveRequestId": "lr_20240618_usr001",
```

## GET /leave/ledger/get

**Get Leave Ledger** — retrieve the leave balance summary for the authenticated employee for a specific leave type.

Use this endpoint to show employees how many days they have remaining before they submit a new request.

### Query Parameters

<ParamField query="leaveType" type="string" required>
  The leave type to query the ledger for (e.g., `"Annual"`, `"Sick"`, `"Casual"`). Must match a type defined in your company's leave policy.
</ParamField>

```bash
curl "https://5bknc0zrv5.execute-api.ap-south-1.amazonaws.com/live/leave/ledger/get?leaveType=Annual" \
  -H "Authorization: Bearer <YOUR_COGNITO_ID_TOKEN>" \
  -H "x-api-key: <YOUR_API_KEY>"
```

```json Response
{
  "message": "Leave ledger retrieved successfully.",
  "responseCode": 200,
  "response": "Success",
  "result": {
    "leaveType": "Annual",
    "totalAllowed": 18,
    "usedLeaves": 5,
    "remainingLeaves": 13,
    "carryForward": 3,
    "pendingApproval": 2
  }
}
```

### Ledger Response Fields

<ResponseField name="leaveType" type="string">
  The leave type this ledger entry corresponds to.
</ResponseField>

<ResponseField name="totalAllowed" type="number">
  Total leave days the employee is entitled to for this type in the current year (including any carry-forward balance).
</ResponseField>

<ResponseField name="usedLeaves" type="number">
  Number of approved leave days already consumed this year.
</ResponseField>

<ResponseField name="remainingLeaves" type="number">
  Leave days still available for use: `totalAllowed − usedLeaves`.
</ResponseField>

<ResponseField name="carryForward" type="number">
  Days carried forward from the previous year and included in `totalAllowed`.
</ResponseField>

<ResponseField name="pendingApproval" type="number">
  Days covered by submitted requests that are still awaiting manager approval. These days are not yet deducted from `remainingLeaves`.
</ResponseField>
