The Messages API powers StaffGlimpse's in-app notification system. Use it to retrieve inbox messages, send alerts to specific users, mark messages as read, and display notification badge counts. Messages are organized into three categories — `inbox` for user-to-user communication, `sent` for outbound records, and `alert` for system-generated notifications — giving you precise control over how your application surfaces information to employees.

**Base URL:** `https://7gt46stdyc.execute-api.ap-south-1.amazonaws.com/live`

<Note>
  Every request to the Messages API requires two headers: `Authorization: Bearer <AWS_Cognito_ID_Token>` and `x-api-key: <static_shared_key>`.
</Note>

## GET /message/get

Retrieve messages for the authenticated user. Filter by category to separate inbox messages, sent items, and system alerts, and use `isRead` to surface only unread notifications.

**Endpoint**

```
GET https://7gt46stdyc.execute-api.ap-south-1.amazonaws.com/live/message/get
```

**Query Parameters**

<ParamField query="msgCategory" type="string">
  Filter messages by category. Accepted values:
  - `inbox` — messages received by the authenticated user
  - `sent` — messages sent by the authenticated user
  - `alert` — system-generated notifications (payroll events, leave approvals, etc.)
</ParamField>
<ParamField query="isRead" type="boolean">
  When `false`, return only unread messages. When `true`, return only read messages. Omit to return all.
</ParamField>
<ParamField query="limit" type="integer">
  Maximum number of messages to return in a single response. Use in combination with `msgCategory` for paginated inbox views.
</ParamField>

<CodeGroup>

```bash cURL — Unread Inbox
curl --request GET \
  --url "https://7gt46stdyc.execute-api.ap-south-1.amazonaws.com/live/message/get?msgCategory=inbox&isRead=false&limit=20" \
  --header "Authorization: Bearer <AWS_Cognito_ID_Token>" \
  --header "x-api-key: <static_shared_key>"
```

```bash cURL — All Alerts
curl --request GET \
  --url "https://7gt46stdyc.execute-api.ap-south-1.amazonaws.com/live/message/get?msgCategory=alert" \
  --header "Authorization: Bearer <AWS_Cognito_ID_Token>" \
  --header "x-api-key: <static_shared_key>"
```

```javascript JavaScript

});

    },
  }

const data = await response.json();
```

</CodeGroup>

**Response**

```json

  "responseCode": 200,
  "response": "Success",
  "result": [
    {
      "msgId": "msg_01PQRSTU",

      "msgCategory": "alert",
      "isRead": false,
      "createdDate": "2024-12-10T14:22:00.000Z"
    },
    {
      "msgId": "msg_02VWXYZA",
      "msgTopic": "Payroll",
      "msgSubject": "November payslip is available",
      "msgBody": "Your payslip for November 2024 has been generated and is available in the Documents section.",
      "msgCategory": "alert",
      "isRead": true,
      "createdDate": "2024-12-01T08:00:00.000Z"
    }

```

<ResponseField name="result[].msgId" type="string">
  Unique identifier for this message. Use this value when calling `PUT /message/update`.
</ResponseField>
<ResponseField name="result[].msgTopic" type="string">
  A short topic label categorizing the message (e.g., `"Payroll"`, `"Leave Request"`).
</ResponseField>
<ResponseField name="result[].msgSubject" type="string">
  The message subject line, displayed as the headline in inbox views.
</ResponseField>
<ResponseField name="result[].msgBody" type="string">
  The full message body text.
</ResponseField>
<ResponseField name="result[].msgCategory" type="string">
  The category this message belongs to — `inbox`, `sent`, or `alert`.
</ResponseField>
<ResponseField name="result[].isRead" type="boolean">
  `true` if the recipient has marked this message as read.
</ResponseField>
<ResponseField name="result[].createdDate" type="string">
  ISO 8601 timestamp of when the message was created.
</ResponseField>

## GET /message/get/count

Retrieve the total and unread message counts for the authenticated user. Use this endpoint to populate notification badge indicators in your application's navigation or header bar.

**Endpoint**

```
GET https://7gt46stdyc.execute-api.ap-south-1.amazonaws.com/live/message/get/count
```

No query parameters are required. The counts are scoped to the authenticated user derived from the `Authorization` token.

<CodeGroup>

```bash cURL
curl --request GET \
  --url "https://7gt46stdyc.execute-api.ap-south-1.amazonaws.com/live/message/get/count" \
  --header "Authorization: Bearer <AWS_Cognito_ID_Token>" \
  --header "x-api-key: <static_shared_key>"
```

```javascript JavaScript
const response = await fetch(
  "https://7gt46stdyc.execute-api.ap-south-1.amazonaws.com/live/message/get/count",
  {
    method: "GET",
    headers: {
      "Authorization": "Bearer <AWS_Cognito_ID_Token>",
      "x-api-key": "<static_shared_key>",
    },
  }
);
const data = await response.json();
```

</CodeGroup>

**Response**

```json
{
  "message": "Message count fetched successfully",
  "responseCode": 200,
  "response": "Success",
  "result": {
    "unreadCount": 4,
    "totalCount": 27
  }
}
```

<ResponseField name="result.unreadCount" type="integer">
  The number of messages that have not yet been marked as read. Display this as the badge count on your notification icon.
</ResponseField>
<ResponseField name="result.totalCount" type="integer">
  The total number of messages in the user's inbox, both read and unread.
</ResponseField>

<Tip>
  Poll `GET /message/get/count` on a short interval (e.g., every 30–60 seconds) to keep notification badges current without fetching full message bodies. Only call `GET /message/get` when the user opens their inbox or the count changes.
</Tip>

## POST /message/create

Send a new message or system notification to one or more users. Specify the target recipients using their user IDs in the `targetUserIds` array.

**Endpoint**

```
POST https://7gt46stdyc.execute-api.ap-south-1.amazonaws.com/live/message/create
```

**Request Body**

<ParamField body="msgTopic" type="string" required>
  A short topic label for the message (e.g., `"Payroll"`, `"Policy Update"`, `"Leave Request"`). Displayed as a tag or grouping header in inbox views.
</ParamField>
<ParamField body="msgSubject" type="string" required>
  The subject line of the message, displayed as the headline in the recipient's inbox.
</ParamField>
<ParamField body="msgBody" type="string" required>
  The full message body. Plain text is recommended; keep it concise and actionable.
</ParamField>
<ParamField body="msgCategory" type="string" required>
  The category for this message. Accepted values:
  - `inbox` — a direct message to the target user(s)
  - `sent` — record a sent message in the sender's sent folder
  - `alert` — a system-generated notification (typically triggered programmatically)
</ParamField>
<ParamField body="targetUserIds" type="array" required>
  An array of user ID strings identifying the recipients of this message. Each entry corresponds to a user's unique identifier within the platform.
</ParamField>

<CodeGroup>

```bash cURL
curl --request POST \
  --url "https://7gt46stdyc.execute-api.ap-south-1.amazonaws.com/live/message/create" \
  --header "Authorization: Bearer <AWS_Cognito_ID_Token>" \
  --header "x-api-key: <static_shared_key>" \
  --header "Content-Type: application/json" \
  --data '{
    "msgTopic": "Policy Update",
    "msgSubject": "Updated Remote Work Policy — Effective January 2025",
    "msgBody": "Please review the updated remote work policy document available in the company portal. The new policy takes effect on January 1, 2025. Contact HR if you have any questions.",
    "msgCategory": "inbox",
    "targetUserIds": ["usr_01ABC", "usr_02DEF", "usr_03GHI"]
  }'
```

```javascript JavaScript
const response = await fetch(
  "https://7gt46stdyc.execute-api.ap-south-1.amazonaws.com/live/message/create",
  {
    method: "POST",
    headers: {
      "Authorization": "Bearer <AWS_Cognito_ID_Token>",
      "x-api-key": "<static_shared_key>",
      "Content-Type": "application/json",
    },
    body: JSON.stringify({
      msgTopic: "Policy Update",
      msgSubject: "Updated Remote Work Policy — Effective January 2025",
      msgBody:
        "Please review the updated remote work policy document available in the company portal. The new policy takes effect on January 1, 2025. Contact HR if you have any questions.",
      msgCategory: "inbox",
      targetUserIds: ["usr_01ABC", "usr_02DEF", "usr_03GHI"],
    }),
  }
);
const data = await response.json();
```

</CodeGroup>

**Response**

```json
{
  "message": "Message sent successfully",
  "responseCode": 200,
  "response": "Success",
  "result": {
    "msgId": "msg_03BCDEFG",
    "msgTopic": "Policy Update",
    "msgSubject": "Updated Remote Work Policy — Effective January 2025",
    "msgCategory": "inbox",
    "targetUserIds": ["usr_01ABC", "usr_02DEF", "usr_03GHI"],
    "createdDate": "2024-12-10T15:45:00.000Z"
  }
}
```

<Tip>
  The `alert` category is intended for system-generated notifications triggered by platform events — for example, when a payroll run completes, a leave request is approved or rejected, or a document is uploaded. Use `inbox` for direct, human-initiated messages between employees. This distinction helps users separate actionable system alerts from colleague communications in their notification feed.
</Tip>

## PUT /message/update

Update a message's read status or active state. The most common use case is marking a message as read after the user opens it, which decrements the unread badge count returned by `GET /message/get/count`.

**Endpoint**

```
PUT https://7gt46stdyc.execute-api.ap-south-1.amazonaws.com/live/message/update
```

**Request Body**

<ParamField body="messageId" type="string" required>
  The unique identifier of the message to update. Returned as `msgId` in `GET /message/get` responses.
</ParamField>
<ParamField body="isRead" type="boolean">
  Set to `true` to mark the message as read, or `false` to mark it as unread.
</ParamField>
<ParamField body="isActive" type="boolean">
  Set to `false` to deactivate (hide) the message without permanently deleting it.
</ParamField>

<CodeGroup>

```bash cURL — Mark as Read
curl --request PUT \
  --url "https://7gt46stdyc.execute-api.ap-south-1.amazonaws.com/live/message/update" \
  --header "Authorization: Bearer <AWS_Cognito_ID_Token>" \
  --header "x-api-key: <static_shared_key>" \
  --header "Content-Type: application/json" \
  --data '{
    "messageId": "msg_01PQRSTU",
    "isRead": true
  }'
```

```bash cURL — Deactivate Message
curl --request PUT \
  --url "https://7gt46stdyc.execute-api.ap-south-1.amazonaws.com/live/message/update" \
  --header "Authorization: Bearer <AWS_Cognito_ID_Token>" \
  --header "x-api-key: <static_shared_key>" \
  --header "Content-Type: application/json" \
  --data '{
    "messageId": "msg_01PQRSTU",
```

