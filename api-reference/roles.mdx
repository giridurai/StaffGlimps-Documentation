The Roles & Permissions API lets you define custom roles within departments and control what each role can read, write, create, delete, import, and export across all platform modules. Combine role definitions with the permissions matrix to build precise, least-privilege access control for every team in your organization.

<Info>
  **Base URL**
  ```
  https://r00buwtnh1.execute-api.ap-south-1.amazonaws.com/live
  ```
</Info>

## Authentication

Every request must include the following headers:

| Header | Value |
|---|---|
| `Authorization` | `Bearer <AWS_Cognito_ID_Token>` |
| `x-api-key` | `<static_shared_key>` |

## Get Role by ID

<p>Retrieve detailed information about a single role using its unique identifier. Use this endpoint to inspect the role's department association, hierarchy position, and current status before making updates.</p>

```
GET /company/role/get?roleId={roleId}
```

### Query Parameters

<ParamField query="roleId" type="string" required>
  The unique identifier of the role to retrieve. Obtain this value from the role list or from the response of `POST /company/role/create`.
</ParamField>

### Request Example

<CodeGroup>
```bash cURL
curl --request GET \
  --url "https://r00buwtnh1.execute-api.ap-south-1.amazonaws.com/live/company/role/get?roleId=role_01HXYZ" \
  --header "Authorization: Bearer <AWS_Cognito_ID_Token>" \
  --header "x-api-key: <static_shared_key>"
```

## Create a Role

<p>Define a new role within a department. After creating a role, call <code>PUT /company/role/permissions/update</code> to assign module-level permissions to it.</p>

```
POST /company/role/create
```

### Request Body

<ParamField body="roleName" type="string" required>
  Display name for the new role (e.g. `"Senior Engineer"`). Must be unique within the department.
</ParamField>

<ParamField body="description" type="string">
  A brief description of the role's responsibilities or scope.
</ParamField>

<ParamField body="departmentId" type="string">
  The identifier of the department this role belongs to. Retrieve department IDs from `GET /company/department/get`.
</ParamField>

<ParamField body="departmentName" type="string">
  Display name of the department. Providing this alongside `departmentId` avoids an extra lookup when rendering UI.
</ParamField>

<ParamField body="equivalentRolePosition" type="string">
  Job title or hierarchy label describing the role's position within the department (e.g. `"Engineering Manager"`, `"Team Lead"`). Displayed in hierarchy views and employee profile cards.
</ParamField>

<ParamField body="designationName" type="string">
  Optional job title or designation to associate with this role (e.g. `"Staff Software Engineer"`). Displayed on employee profile cards.
</ParamField>

### Request Example

<CodeGroup>
```bash cURL
curl --request POST \
  --url "https://r00buwtnh1.execute-api.ap-south-1.amazonaws.com/live/company/role/create" \
  --header "Authorization: Bearer <AWS_Cognito_ID_Token>" \
  --header "x-api-key: <static_shared_key>" \
  --header "Content-Type: application/json" \
  --data '{
    "roleName": "Engineering Manager",
    "description": "Manages the engineering department and its sub-teams",
    "departmentId": "dept_01HXYZ",
    "departmentName": "Engineering",
    "equivalentRolePosition": "Engineering Manager",
    "designationName": "Engineering Manager"
  }'
```

## Update a Role

<p>Modify an existing role's attributes. Supply only the fields you need to change — all other attributes retain their current values. To soft-delete a role, set <code>isDeleted</code> to <code>true</code> after verifying no users are assigned.</p>

```
PUT /company/role/update
```

### Request Body

<ParamField body="roleId" type="string" required>
  Unique identifier of the role to update.
</ParamField>

<ParamField body="roleName" type="string">
  New display name for the role.
</ParamField>

<ParamField body="description" type="string">
  Updated description of the role's responsibilities.
</ParamField>

<ParamField body="departmentId" type="string">
  Reassign this role to a different department by supplying the target department's ID.
</ParamField>

<ParamField body="equivalentRolePosition" type="string">
  Updated hierarchy label for the role within the department (e.g. `"IT Director"`).
</ParamField>

<ParamField body="isActive" type="boolean">
  Set to `false` to deactivate the role without deleting it. Inactive roles cannot be assigned to new users.
</ParamField>

<ParamField body="isDeleted" type="boolean">
  Set to `true` to soft-delete the role. Before setting this, call `GET /company/role/users/count?roleId={roleId}` to confirm no users are assigned.
</ParamField>

### Request Example

<CodeGroup>

## Delete a Role

<p>Soft-delete a role by its ID. The role is marked as deleted and removed from all assignment interfaces, but historical records that referenced it are preserved for audit purposes.</p>

```
GET /company/role/delete?roleId={roleId}
```

<Warning>
  Before deleting a role, verify that no users are currently assigned to it by calling `GET /company/role/users/count?roleId={roleId}`. If `userCount` is greater than `0`, reassign those users to another role first. Deleting a role with active users may result in those employees losing their access permissions.
</Warning>

## Update Role Permissions

<p>Replace or update the permissions matrix for a role. Supply the full <code>permissions</code> array — any module entry you include overwrites the existing permission flags for that module. Modules omitted from the request are not modified.</p>

```
PUT /company/role/permissions/update
```

<Note>
  Send the complete permissions array for every module you want to configure. Partial updates within a module object (e.g. setting only `read` and leaving others undefined) will set the omitted flags to `false`.
</Note>

### Request Body

<ParamField body="roleId" type="string" required>
  Unique identifier of the role whose permissions you want to update.
</ParamField>

<ParamField body="permissions" type="array" required>
  Array of module permission objects. Each object must include `module` and at least one permission flag.

  <Expandable title="Permission object fields">
    <ParamField body="module" type="string" required>
      The name of the platform module (e.g. `"Users"`, `"Attendance"`, `"Documents"`, `"LeaveRequests"`).
    </ParamField>

    <ParamField body="read" type="boolean">
      Grant or revoke read access for the module.
    </ParamField>

    <ParamField body="write" type="boolean">
      Grant or revoke write (edit) access for the module.
    </ParamField>

    <ParamField body="create" type="boolean">
      Grant or revoke the ability to create new records in the module.
    </ParamField>

    <ParamField body="delete" type="boolean">
      Grant or revoke the ability to delete records in the module.
    </ParamField>

    <ParamField body="import" type="boolean">
      Grant or revoke bulk import access for the module.
    </ParamField>

    <ParamField body="export" type="boolean">
      Grant or revoke the ability to export data from the module.
    </ParamField>
  </Expandable>
</ParamField>
