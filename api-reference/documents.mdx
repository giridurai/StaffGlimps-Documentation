The Documents API stores employee-related files in AWS S3 and serves them through CloudFront. You can upload any file type, manage metadata like categories and tags, and securely download documents. Uploads and metadata operations go through the Documents API base URL, while file downloads are served directly from the CloudFront distribution.

**Upload / Metadata Base URL:** `https://6e52pmjmy4.execute-api.ap-south-1.amazonaws.com/live`

**Download Base URL:** `https://d2ikeisatr21la.cloudfront.net`

---

## Authentication

Every request to the Documents API requires both of the following headers:

| Header | Value |
|---|---|
| `Authorization` | `Bearer <AWS_Cognito_ID_Token>` |
| `x-api-key` | `<static_shared_key>` |

<Note>
  File downloads from CloudFront use a **different** authentication header. See [Download a Document](#get-documentid-cloudfront) for details.
</Note>

## POST /document

**Upload a Document** — upload a file to cloud storage using a `multipart/form-data` request.

Send the file along with optional metadata fields in a single multipart request. After a successful upload, the API returns a `documentId` you can store and reference in other API calls (e.g., when attaching a document to a leave request).

### Form Fields

<ParamField body="file" type="binary" required>
  The file to upload. Any file type is accepted. The content type is inferred from the file's MIME type.
</ParamField>

<ParamField body="documentCategory" type="string">
  An optional label categorising the document (e.g., `"Medical Certificate"`, `"ID Proof"`, `"Contract"`).
</ParamField>

<CodeGroup>

```bash cURL
curl -X POST \
  https://6e52pmjmy4.execute-api.ap-south-1.amazonaws.com/live/document \
  -H "Authorization: Bearer <YOUR_COGNITO_ID_TOKEN>" \
  -H "x-api-key: <YOUR_API_KEY>" \
  -F "file=@/path/to/medical_certificate.pdf" \
  -F "documentCategory=Medical Certificate"
```

```javascript JavaScript (fetch)
const formData = new FormData();
formData.append("file", fileInput.files[0]);
formData.append("documentCategory", "Medical Certificate");

const response = await fetch(
  "https://6e52pmjmy4.execute-api.ap-south-1.amazonaws.com/live/document",
  {
    method: "POST",
    headers: {
      Authorization: "Bearer <YOUR_COGNITO_ID_TOKEN>",
      "x-api-key": "<YOUR_API_KEY>",
    },
    body: formData,
  }
);

const data = await response.json();
console.log(data.result.documentId); // "doc_new888"
```

</CodeGroup>

```json Response
{
  "message": "Document uploaded successfully.",
  "responseCode": 200,
  "response": "Success",
  "result": {
    "documentId": "doc_new888"
  }
}
```

## GET /document/get

**Get Document by ID** — retrieve the full metadata record for a document by its ID.

Use this endpoint to display document details in your UI, verify a document's current state, or confirm that a file was uploaded correctly before referencing it elsewhere.

### Query Parameters

<ParamField query="documentId" type="string" required>
  The unique identifier of the document to retrieve (e.g., `doc_new888`).
</ParamField>

```bash
curl "https://6e52pmjmy4.execute-api.ap-south-1.amazonaws.com/live/document/get?documentId=doc_new888" \
  -H "Authorization: Bearer <YOUR_COGNITO_ID_TOKEN>" \
  -H "x-api-key: <YOUR_API_KEY>"
```

```json Response
{
  "message": "Document retrieved successfully.",
  "responseCode": 200,
  "response": "Success",
  "result": {
    "documentId": "doc_new888",
    "fileName": "medical_certificate.pdf",
    "documentCategory": "Medical Certificate",
    "contentType": "application/pdf",
    "description": "",
    "tags": [],
    "isSigned": false,
    "isEncrypted": false,
    "isShared": false,
    "isSensitive": true,
    "isDeleted": false,
    "isActive": true,
    "isPublic": false,
    "isVersioned": false,
    "version": 1,
    "createdDate": "2024-06-15T10:22:00.000Z",
    "createdBy": "usr_001",
    "s3Key": "documents/usr_001/doc_new888/medical_certificate.pdf"
  }
}
```

### Response Fields

<ResponseField name="documentId" type="string">
  Unique identifier for this document record.
</ResponseField>

<ResponseField name="fileName" type="string">
  Original file name at the time of upload.
</ResponseField>

<ResponseField name="documentCategory" type="string">
  Category label assigned to this document (e.g., `"Medical Certificate"`, `"ID Proof"`).
</ResponseField>

<ResponseField name="contentType" type="string">
  MIME type of the uploaded file (e.g., `"application/pdf"`, `"image/jpeg"`).
</ResponseField>

<ResponseField name="version" type="integer">
  Current version number of the document. Starts at `1` and increments with each update when versioning is enabled.
</ResponseField>

<ResponseField name="isSensitive" type="boolean">
  When `true`, the document is flagged as sensitive and access may be restricted to authorised roles.
</ResponseField>

<ResponseField name="isVersioned" type="boolean">
  When `true`, the system retains previous versions of this document when it is updated.
</ResponseField>

<ResponseField name="s3Key" type="string">
  The S3 object key representing the full path to the file in storage. Use this path when constructing direct CloudFront download URLs.
</ResponseField>

| `documentCategory` | string | Category label for the document |

| `isVersioned` | boolean | Whether versioning is enabled for this document |

| `createdDate` | string | ISO 8601 timestamp of upload |

## PUT /document/update

**Update Document Metadata** — modify the metadata fields of an existing document.

Use this endpoint to re-categorise a document, toggle its active state, or soft-delete it. You do not need to re-upload the file — only the metadata fields are updated.

<Warning>
  Setting `isDeleted: true` will perform a **soft delete** and exclude the document from `GET /document/get` queries. The file remains in storage. To restore a soft-deleted document, send a subsequent update with `isDeleted: false`.
</Warning>

### Request Body

<ParamField body="documentId" type="string" required>
  The ID of the document to update.
</ParamField>

<ParamField body="documentCategory" type="string">
  Updated category label for the document.
</ParamField>

<ParamField body="isActive" type="boolean">
  Set to `false` to deactivate the document without deleting it.
</ParamField>

<ParamField body="isDeleted" type="boolean">
  Set to `true` to soft-delete the document. Set to `false` to restore a previously deleted document.
</ParamField>

<Tabs>
  <Tab title="Update Category">

```bash
curl -X PUT \
  https://6e52pmjmy4.execute-api.ap-south-1.amazonaws.com/live/document/update \
  -H "Authorization: Bearer <YOUR_COGNITO_ID_TOKEN>" \
  -H "x-api-key: <YOUR_API_KEY>" \
  -H "Content-Type: application/json" \
  -d '{
    "documentId": "doc_new888",
    "documentCategory": "Verified Medical Certificate"
  }'
```

```json Response
{
  "message": "Document updated successfully.",
  "responseCode": 200,
  "response": "Success",
  "result": {
    "documentId": "doc_new888",
    "documentCategory": "Verified Medical Certificate",
    "updatedAt": "2024-06-16T09:00:00.000Z"
  }
}
```

## GET /{documentId} — CloudFront Download

**Download a Document** — stream the binary file content directly from the CloudFront distribution.

Construct the download URL by appending the `documentId` to the CloudFront base URL. This request is served from the edge network and does **not** go through the Documents API gateway.

**Download URL:** `https://d2ikeisatr21la.cloudfront.net/{documentId}`

<Note>
  CloudFront downloads use the `x-token` header to carry your Cognito ID token — **not** the `Authorization: Bearer` header used by all other StaffGlimpse API endpoints. Requests that send `Authorization` instead of `x-token` will be rejected by the CloudFront distribution.
</Note>

```bash
curl https://d2ikeisatr21la.cloudfront.net/doc_new888 \
  -H "x-token: <YOUR_COGNITO_ID_TOKEN>" \
  --output medical_certificate.pdf
```

The response body is the raw binary content of the file. Use the `--output` flag (cURL) or stream the response body to a file in your application.

<Tip>
  Set the output file extension based on the `contentType` value you retrieved from `GET /document/get` beforehand. For example, `application/pdf` → `.pdf`, `image/jpeg` → `.jpg`.
</Tip>

### Header Reference

| Header | Required For | Value |
|---|---|---|
| `Authorization` | All Documents API calls (upload, metadata, update) | `Bearer <AWS_Cognito_ID_Token>` |
| `x-api-key` | All Documents API calls (upload, metadata, update) | Static shared API key |
| `x-token` | CloudFront downloads **only** | `<AWS_Cognito_ID_Token>` (no `Bearer` prefix) |
