StaffGlimpse's leave system has two distinct layers — company admins configure leave policies and holidays that govern what employees are entitled to, while employees submit leave requests that managers can approve or reject. Every API call requires both an `Authorization: Bearer <token>` header containing your AWS Cognito ID token and an `x-api-key: <key>` header carrying your static shared key.

---

## Leave Policies

Admins define leave policies at the location level, scoping entitlements by country, province, city, and named office. Each policy lists one or more leave types — such as Annual, Sick, or Casual — along with annual allowances, carry-forward limits, application rules, and gender eligibility.

### Create a Policy

Send a `POST` request to `/company/leave/create` on the Company API base URL.

```bash
curl -X POST https://r00buwtnh1.execute-api.ap-south-1.amazonaws.com/live/company/leave/create \
  -H "Content-Type: application/json" \
  -H "x-api-key: <YOUR_API_KEY>" \
  -H "Authorization: Bearer <YOUR_TOKEN>" \
  -d '{
    "metadata": "leavePolicy",
    "location": {
      "country": "IN",
      "province": "Maharashtra",
      "city": "Mumbai",
      "locationName": "Head Office"
    },
    "leavePolicy": [
      {
        "type": "Annual",
        "perAnnum": 20,
        "frequency": "yearly",
        "carryForward": 5,
        "rules": "Must be applied 14 days in advance",
        "gender": "all"
      },
      {
        "type": "Sick",
        "perAnnum": 10,
        "frequency": "yearly",
        "carryForward": 0,
        "rules": "Medical certificate required for 3+ days",
        "gender": "all"
      }
    ]
  }'
```

<Expandable title="Leave Policy Fields">
  <ParamField body="metadata" type="string" required>
    Must be `"leavePolicy"` to route the request to the leave policy handler.
  </ParamField>

  <ParamField body="location.country" type="string" required>
    ISO 3166-1 alpha-2 country code (e.g. `"IN"` for India, `"US"` for the United States).
  </ParamField>

  <ParamField body="location.province" type="string" required>
    State or province name as used in your location master data.
  </ParamField>

  <ParamField body="location.city" type="string" required>
    City name as used in your location master data.
  </ParamField>

  <ParamField body="location.locationName" type="string" required>
    Friendly office or site name (e.g. `"Head Office"`, `"Remote"`).
  </ParamField>

  <ParamField body="leavePolicy" type="array" required>
    Array of leave type objects. Each object defines a single leave category.
  </ParamField>

  <ParamField body="leavePolicy[].type" type="string" required>
    Leave category name, e.g. `"Annual"`, `"Sick"`, `"Casual"`, `"Maternity"`.
  </ParamField>

  <ParamField body="leavePolicy[].perAnnum" type="number" required>
    Total days an employee is entitled to in a calendar year.
  </ParamField>

  <ParamField body="leavePolicy[].frequency" type="string" required>
    Accrual frequency. Typically `"yearly"`.
  </ParamField>

  <ParamField body="leavePolicy[].carryForward" type="number" required>
    Maximum unused days that roll over to the next year. Set to `0` to disallow carry-forward.
  </ParamField>

  <ParamField body="leavePolicy[].rules" type="string">
    Free-text eligibility or application rules displayed to employees.
  </ParamField>

  <ParamField body="leavePolicy[].gender" type="string">
    Restrict the leave type by gender. Use `"all"` to make it available to everyone, or `"female"` / `"male"` for gender-specific leave types such as Maternity or Paternity.
  </ParamField>
</Expandable>

### Update a Policy

To modify an existing policy, send the same request body structure to `PUT /company/leave/update`. Include all leave types in `leavePolicy` — the array replaces the existing policy for that location.

```bash
curl -X PUT https://r00buwtnh1.execute-api.ap-south-1.amazonaws.com/live/company/leave/update \
  -H "Content-Type: application/json" \
  -H "x-api-key: <YOUR_API_KEY>" \
  -H "Authorization: Bearer <YOUR_TOKEN>" \
  -d '{
    "metadata": "leavePolicy",
    "location": {
      "country": "IN",
      "province": "Maharashtra",
      "city": "Mumbai",
      "locationName": "Head Office"
    },
    "leavePolicy": [
      {
        "type": "Annual",
        "perAnnum": 22,
        "frequency": "yearly",
        "carryForward": 5,
        "rules": "Must be applied 14 days in advance",
        "gender": "all"
      }
    ]
  }'
```

## National & Regional Holidays

Retrieve holiday calendars to display in scheduling UIs or to calculate accurate leave day counts. StaffGlimpse provides two separate endpoints — one for country-wide public holidays and one for location-specific regional observances.

<Tabs>
  <Tab title="National Holidays">
    Fetch public holidays that apply to an entire country.

    ```bash
    curl -X GET "https://r00buwtnh1.execute-api.ap-south-1.amazonaws.com/live/company/leave/get?metadata=nationalHolidays&year=2024&country=IN" \
      -H "x-api-key: <YOUR_API_KEY>" \
      -H "Authorization: Bearer <YOUR_TOKEN>"
    ```

    | Query Parameter | Required | Description |
    |---|---|---|
    | `metadata` | Yes | Must be `nationalHolidays` |
    | `year` | Yes | Four-digit calendar year, e.g. `2024` |
    | `country` | Yes | ISO 3166-1 alpha-2 country code |

  </Tab>
  <Tab title="Regional Holidays">
    Fetch holidays specific to a province, city, or named location.

    ```bash
    curl -X GET "https://r00buwtnh1.execute-api.ap-south-1.amazonaws.com/live/company/leave/get?metadata=provinceHolidays&year=2024&country=IN&province=Maharashtra&city=Mumbai&locationName=Head+Office" \
      -H "x-api-key: <YOUR_API_KEY>" \
      -H "Authorization: Bearer <YOUR_TOKEN>"
    ```

    | Query Parameter | Required | Description |
    |---|---|---|
    | `metadata` | Yes | Must be `provinceHolidays` |
    | `year` | Yes | Four-digit calendar year |
    | `country` | Yes | ISO 3166-1 alpha-2 country code |
    | `province` | Yes | Province or state name |
    | `city` | No | City name to further narrow results |
    | `locationName` | No | Office name to further narrow results |

  </Tab>
</Tabs>

Both endpoints return an array of holiday objects with the following shape:

```json
{
  "date": "2024-01-26",
  "name": "Republic Day",
  "type": "national",
  "description": "National holiday commemorating the Constitution of India.",
  "isOptional": false
}
```

<ResponseField name="date" type="string (YYYY-MM-DD)">
  Calendar date of the holiday.
</ResponseField>

<ResponseField name="name" type="string">
  Display name of the holiday.
</ResponseField>

<ResponseField name="type" type="string">
  Scope of the holiday — `"national"`, `"provincial"`, or `"local"`.
</ResponseField>

<ResponseField name="description" type="string">
  Brief description shown in employee-facing calendar views.
</ResponseField>

<ResponseField name="isOptional" type="boolean">
  When `true`, employees may choose whether to observe this holiday. Optional holidays typically count against the employee's annual leave balance if taken.
</ResponseField>

## Checking Leave Balance

Employees can inspect how many days remain for each leave type before submitting a request.

**Quick balance check** — call the Attendance module's leave status endpoint to get a concise summary:

```bash
curl -X GET https://xes7huej2d.execute-api.ap-south-1.amazonaws.com/live/attendance/leave/status \
  -H "x-api-key: <YOUR_API_KEY>" \
  -H "Authorization: Bearer <YOUR_TOKEN>"
```

The response shows remaining and pending days per leave type for the authenticated user.

**Detailed ledger** — for a full transaction history (entitlements, deductions, carry-forwards) use the Leave API ledger endpoint:

```bash
curl -X GET "https://5bknc0zrv5.execute-api.ap-south-1.amazonaws.com/live/leave/ledger/get?leaveType=Annual" \
  -H "x-api-key: <YOUR_API_KEY>" \
  -H "Authorization: Bearer <YOUR_TOKEN>"
```

Pass any valid leave type (`Annual`, `Sick`, `Casual`, etc.) as the `leaveType` query parameter to filter the ledger to that category.

## Submitting a Leave Request

Employees create a leave request by posting to `/leave/request/create` on the Leave API. Provide the leave type, date range, number of days, and a reason. Optionally attach previously uploaded document IDs as supporting evidence (for example, a medical certificate for sick leave).

```bash
curl -X POST https://5bknc0zrv5.execute-api.ap-south-1.amazonaws.com/live/leave/request/create \
  -H "Content-Type: application/json" \
  -H "x-api-key: <YOUR_API_KEY>" \
  -H "Authorization: Bearer <YOUR_TOKEN>" \
  -d '{
    "leaveType": "Annual",
    "fromDate": "2024-12-20",
    "toDate": "2024-12-23",
    "days": 4,
    "reason": "Family vacation",
    "documents": []
  }'
```

<ParamField body="leaveType" type="string" required>
  Must match a leave type defined in the employee's applicable leave policy, e.g. `"Annual"`, `"Sick"`, `"Casual"`.
</ParamField>

<ParamField body="fromDate" type="string (YYYY-MM-DD)" required>
  First day of the requested leave period.
</ParamField>

<ParamField body="toDate" type="string (YYYY-MM-DD)" required>
  Last day of the requested leave period (inclusive).
</ParamField>

<ParamField body="days" type="number" required>
  Number of working days within the requested range. Weekends and public holidays do not count toward this total.
</ParamField>

<ParamField body="reason" type="string" required>
  Employee's stated reason for the leave, visible to the approving manager.
</ParamField>

<ParamField body="documents" type="array">
  Array of document IDs (strings) uploaded via the Documents API. Include a medical certificate ID here for sick leave requests that require one.
</ParamField>

## Manager Approval

Managers review and act on leave requests using `POST /leave/request/update` with the `type=manager` query parameter.

### Approve a Request

```bash
curl -X POST "https://5bknc0zrv5.execute-api.ap-south-1.amazonaws.com/live/leave/request/update?type=manager" \
  -H "Content-Type: application/json" \
  -H "x-api-key: <YOUR_API_KEY>" \
  -H "Authorization: Bearer <YOUR_TOKEN>" \
  -d '{
    "leaveRequestId": "lr_100",
    "userId": "emp_001",
    "action": "approve",
    "comments": "Enjoy your vacation!",
    "managerComments": "Team is covered"
  }'
```

### Reject a Request

Use the same endpoint and body, but set `"action": "reject"` and update your comments accordingly:

```json
{
  "leaveRequestId": "lr_100",
  "userId": "emp_001",
  "action": "reject",
  "comments": "Insufficient coverage during this period.",
  "managerComments": "Please reschedule to next month."
}
```

<ParamField body="leaveRequestId" type="string" required>
  Unique identifier of the leave request to act on.
</ParamField>

<ParamField body="userId" type="string" required>
  User ID of the employee who submitted the request.
</ParamField>

<ParamField body="action" type="string" required>
  The decision to record. Accepted values are `"approve"` and `"reject"`.
</ParamField>

<ParamField body="comments" type="string">
  Comments visible to the employee explaining the decision.
</ParamField>

<ParamField body="managerComments" type="string">
  Internal notes visible only to other managers and HR administrators.
</ParamField>

### Employee Cancellation

Employees can cancel their own pending requests using the same endpoint with `type=user`:

```bash
curl -X POST "https://5bknc0zrv5.execute-api.ap-south-1.amazonaws.com/live/leave/request/update?type=user" \
  -H "Content-Type: application/json" \
  -H "x-api-key: <YOUR_API_KEY>" \
  -H "Authorization: Bearer <YOUR_TOKEN>" \
  -d '{
    "leaveRequestId": "lr_100",
    "action": "cancel"
  }'
```

<Warning>
  Cancellation is only permitted while a request is still in `PENDING` status. Once a manager has approved or rejected a request, the employee must contact HR to make any changes.
</Warning>

## Leave Request Statuses

Every leave request moves through the following lifecycle:

| Status | Meaning |
|---|---|
| `PENDING` | The request has been submitted and is awaiting manager review. |
| `APPROVED` | The manager has approved the request; leave days are deducted from the employee's balance. |
| `REJECTED` | The manager has rejected the request; no leave days are deducted. |
| `CANCELLED` | The employee cancelled the request before it was acted upon. |

<Tip>
  Managers can retrieve all pending requests assigned to them with `GET /leave/request/get?type=manager` on the Leave API. Employees can look up a specific request with `GET /leave/request/get?leaveRequestId={id}`, replacing `{id}` with the target leave request ID.
</Tip>
