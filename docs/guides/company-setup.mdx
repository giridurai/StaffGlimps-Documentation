Before your employees can use StaffGlimpse, you need to register your company and build out your organizational structure — departments and roles. This guide walks you through each step in order, from initial registration to a fully configured role hierarchy ready for employee onboarding.

<Tip>
  Set up all departments and roles before creating users. Users are assigned to a department and role at creation time, so having your organizational structure in place first prevents rework.
</Tip>

## 1. Register Your Company

Send a `POST /company/register` request to create your company account. This registers your organization as a new tenant in StaffGlimpse and generates your company profile.

<ParamField body="name" type="string" required>
  The display name of your company as it appears across the platform (for example, `"Acme Corporation"`).
</ParamField>

<ParamField body="email" type="string" required>
  The admin email address used to manage the company account and receive billing notifications.
</ParamField>

<ParamField body="password" type="string" required>
  The password for the initial admin account. Must meet your configured password-complexity policy.
</ParamField>

<ParamField body="confirmPassword" type="string" required>
  Must match the value provided in `password`. The API returns a validation error if the two values differ.
</ParamField>

```bash
curl -X POST https://r00buwtnh1.execute-api.ap-south-1.amazonaws.com/live/company/register \
  -H "Content-Type: application/json" \
  -H "x-api-key: <YOUR_API_KEY>" \
  -H "Authorization: Bearer <YOUR_TOKEN>" \
  -d '{
    "name": "Acme Corporation",
    "email": "admin@acme.com",
    "password": "SecurePass123!",
    "confirmPassword": "SecurePass123!"
  }'
```

A successful registration returns a `200` response containing your new company's unique identifier. Store this — you will need it for subsequent requests.

## 2. View Your Company Profile

After registration, retrieve your full company profile at any time with a `GET /company` request. No request body is required; your `Authorization` header identifies the company.

```bash
curl -X GET https://r00buwtnh1.execute-api.ap-south-1.amazonaws.com/live/company \
  -H "x-api-key: <YOUR_API_KEY>" \
  -H "Authorization: Bearer <YOUR_TOKEN>"
```

The `result` object in the response includes the following fields:

<ResponseField name="CompanyName" type="string">
  The registered display name of your company.
</ResponseField>

<ResponseField name="Email" type="string">
  The admin email address associated with the account.
</ResponseField>

<ResponseField name="AccountURL" type="string">
  The unique subdomain or URL assigned to your company's StaffGlimpse tenant.
</ResponseField>

<ResponseField name="Plan" type="string">
  The subscription plan currently active on the account (for example, `"Pro"` or `"Enterprise"`).
</ResponseField>

<ResponseField name="Status" type="string">
  The current account status — typically `"Active"` or `"Suspended"`.
</ResponseField>

<ResponseField name="BillCycle" type="string">
  The billing frequency: `"Monthly"` or `"Annually"`.
</ResponseField>

<ResponseField name="ExpiringDate" type="string">
  The ISO 8601 date on which the current subscription period ends.
</ResponseField>

```json
{
  "message": "Company profile retrieved successfully",
  "responseCode": 200,
  "response": "Success",
  "result": {
    "CompanyName": "Acme Corporation",
    "Email": "admin@acme.com",
    "AccountURL": "https://acme.staffglimpse.com",
    "Plan": "Pro",
    "Status": "Active",
    "BillCycle": "Monthly",
    "ExpiringDate": "2025-08-01"
  }
}
```

## 3. Create Departments

Departments represent the functional groups within your organization. Use `POST /company/department/create` to add each one.

```bash
curl -X POST https://r00buwtnh1.execute-api.ap-south-1.amazonaws.com/live/company/department/create \
  -H "Content-Type: application/json" \
  -H "x-api-key: <YOUR_API_KEY>" \
  -H "Authorization: Bearer <YOUR_TOKEN>" \
  -d '{
    "departmentName": "Engineering",
    "description": "Software development team",
    "noOfEmployees": 45,
    "isActive": true,
    "status": "Active"
  }'
```

<ParamField body="departmentName" type="string" required>
  A unique, human-readable name for the department (for example, `"Engineering"` or `"Human Resources"`).
</ParamField>

<ParamField body="description" type="string">
  A short description of the department's function or scope.
</ParamField>

<ParamField body="noOfEmployees" type="integer">
  The expected headcount for this department. Used for reporting and planning purposes.
</ParamField>

<ParamField body="isActive" type="boolean">
  Set to `true` to make the department immediately available for user assignment.
</ParamField>

<ParamField body="status" type="string">
  Human-readable status string. Use `"Active"` for live departments.
</ParamField>

### List Existing Departments

Retrieve all departments you have created with `GET /company/department/get`. You can narrow the results using optional query parameters.

```bash
# Return all departments
curl -X GET https://r00buwtnh1.execute-api.ap-south-1.amazonaws.com/live/company/department/get \
  -H "x-api-key: <YOUR_API_KEY>" \
  -H "Authorization: Bearer <YOUR_TOKEN>"

# Filter by name — exact match
curl -X GET "https://r00buwtnh1.execute-api.ap-south-1.amazonaws.com/live/company/department/get?departmentName=Engineering&matchType=like" \
  -H "x-api-key: <YOUR_API_KEY>" \
  -H "Authorization: Bearer <YOUR_TOKEN>"
```

<ParamField query="departmentName" type="string">
  Filter results to departments whose name matches this value. Combine with `matchType` to control matching behaviour.
</ParamField>

<ParamField query="matchType" type="string">
  Controls how `departmentName` is matched. Accepted values:
  - `like` — returns departments whose name contains the search string.
  - `startsWith` — returns departments whose name begins with the search string.
</ParamField>

## 4. Create Roles

Roles define the job positions and permission tiers available within a department. Use `POST /company/role/create` to add each role. Repeat this step for every unique position in your organization.

```bash
curl -X POST https://r00buwtnh1.execute-api.ap-south-1.amazonaws.com/live/company/role/create \
  -H "Content-Type: application/json" \
  -H "x-api-key: <YOUR_API_KEY>" \
  -H "Authorization: Bearer <YOUR_TOKEN>" \
  -d '{
    "roleName": "Engineering Manager",
    "description": "Team lead with elevated permissions",
    "departmentId": "dep_001",
    "departmentName": "Engineering",
    "equivalentRolePosition": "Engineering Manager",
    "designationName": "Manager"
  }'
```

<ParamField body="roleName" type="string" required>
  A unique name for the role within the department (for example, `"Engineering Manager"`).
</ParamField>

<ParamField body="description" type="string">
  A brief summary of the role's responsibilities and access level.
</ParamField>

<ParamField body="departmentId" type="string" required>
  The unique identifier of the department this role belongs to. Returned when you created the department.
</ParamField>

<ParamField body="departmentName" type="string">
  The display name of the associated department. Used for labelling in reports and the UI.
</ParamField>

<ParamField body="equivalentRolePosition" type="string">
  A label used to map this role to a standard position in your org chart.
</ParamField>

<ParamField body="designationName" type="string">
  The formal job designation shown on employee profiles and documents (for example, `"Manager"` or `"Senior Engineer"`).
</ParamField>

## 5. Set Role Permissions

After creating a role, configure exactly which modules it can access using `PUT /company/role/permissions/update`. Each module in the permissions matrix accepts a granular set of boolean flags.

```bash
curl -X PUT https://r00buwtnh1.execute-api.ap-south-1.amazonaws.com/live/company/role/permissions/update \
  -H "Content-Type: application/json" \
  -H "x-api-key: <YOUR_API_KEY>" \
  -H "Authorization: Bearer <YOUR_TOKEN>" \
  -d '{
    "roleId": "role_001",
    "permissions": {
      "attendance": {
        "view": true,
        "create": true,
        "edit": true,
        "delete": false
      },
      "leave": {
        "view": true,
        "create": true,
        "edit": true,
        "delete": false,
        "approve": true
      },
      "documents": {
        "view": true,
        "create": false,
        "edit": false,
        "delete": false
      }
    }
  }'
```

<Note>
  Permissions are evaluated at request time. If you update a role's permissions, the change takes effect immediately for all users assigned to that role — no re-login is required.
</Note>

<Accordion title="Recommended permissions by role type">
  **Admin / HR Manager** — enable `view`, `create`, `edit`, `delete`, and `approve` across all modules.

  **Department Manager** — enable `view`, `create`, `edit`, and `approve` for attendance and leave modules; restrict `delete` and payroll modules.

  **Standard Employee** — enable `view` and `create` for attendance and leave; disable all `edit`, `delete`, and `approve` flags.
</Accordion>
