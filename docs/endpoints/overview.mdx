StaffGlimpse routes different API domains through separate AWS API Gateway endpoints. Each service has its own base URL — use the correct base URL when constructing requests for each domain. Mixing up base URLs across services is the most common source of `404` errors when first integrating with the platform.

<Tip>
  All endpoints require both the `Authorization: Bearer <token>` and `x-api-key` headers. The one exception is document downloads from CloudFront, which use an `x-token` header instead of `Authorization`.
</Tip>

## Regions

All production APIs are served from `ap-south-1` (Mumbai, India). Latency may vary depending on your geographic location. If you are building an integration for users in Europe or the Americas, account for the additional round-trip time when setting client-side timeouts.

<Info>
  The Document Cloud base URL (`d2ikeisatr21la.cloudfront.net`) is a CloudFront distribution, not an API Gateway endpoint. It is globally cached via AWS edge locations — download latency is lower than the API Gateway services regardless of your region.
</Info>

## Content Type

All request bodies must use `Content-Type: application/json` unless the endpoint accepts file uploads. The only exception is `POST /document`, which requires `Content-Type: multipart/form-data` so that binary file data can be included alongside form fields.

<Warning>
  Sending a JSON body to `POST /document` will result in an error. Always use `multipart/form-data` for that endpoint.
</Warning>
